# クイックスタート: タスク削除の検証

## 事前準備

- Java 21、Node.js 24、pnpm 10
- DockerとPostgreSQL 17
- 削除対象となる有効なタスク。関連データの整合性を確認する場合は、関連する`TaskDependency`と`WorkLog`も用意する

本機能ではタスクを登録しない。対象データには、共通基盤が提供する既存データまたはテスト用fixtureを使う。

## 開発用データベースの起動

リポジトリのルートで実行する:

```bash
docker compose up -d postgres
```

## 自動検証

依存関係の初回セットアップ時または変更時に実行する:

```bash
pnpm --dir frontend install --frozen-lockfile
```

バックエンドの検証:

```bash
cd backend
./mvnw test
```

フロントエンドの検証:

```bash
pnpm --dir frontend test
pnpm --dir frontend build
```

## 受け入れ確認の手順

1. 開発用データベースまたはテスト用fixtureに、有効な対象タスクと、対象に接続する依存関係・実績記録を用意する。
2. フロントエンドで一覧を開き、対象タスクの削除操作を選ぶ。確認内容に対象タスクを識別できる情報があることを確認する。
3. 確認をキャンセルする。削除APIが呼び出されず、タスクと関連データが変わらないことを確認する。
4. 同じ対象の削除を確定する。APIが204を返し、完了メッセージが表示され、対象タスクが一覧から消えることを確認する。
5. データを確認し、対象タスクの論理削除日時が設定され、接続する依存関係が削除され、実績記録と無関係な依存関係が保持されていることを確認する。
6. 存在しない、または削除済みのIDを指定して削除し、404相当のエラーが表示され、他のタスクや関連データが変わらないことを確認する。

CIと同等の検証は、リポジトリのルートで`bash scripts/gate.sh verify`を実行する。必要なPostgreSQLが起動していることを確認する。
