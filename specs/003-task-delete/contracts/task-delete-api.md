# タスク削除API契約

共通エラー形式と削除対象の関連データ規則は[API契約](../../../docs/design/api-contract.md)に従う。JSON形式のREST APIを使用する。

## タスクの削除

`DELETE /api/tasks/{taskId}`

- 削除確認は画面側で対象を示して行う。利用者がキャンセルした場合、APIを呼び出さない。
- 利用者が確定した場合にのみDELETE要求を送る。

応答:

| ステータス | 意味 |
|---|---|
| `204 No Content` | タスクを論理削除した。応答本文なし |
| `404 Not Found` | タスクが存在しない、または論理削除済み。他のデータは変更しない |

## データ整合性

- タスクの論理削除と、対象タスクが先行または後続として関わる依存関係の削除は一処理として行う。
- 実績記録を保持し、無関係な依存関係も保持する。
- 削除されたタスクを経由していた関係を自動でつなぎ直さない。
- 失敗時に部分更新を残さず、成功扱いの応答を返さない。

## 画面操作の契約

- 一覧の各タスクに削除操作を表示する。
- 削除操作後、対象を特定できる確認を表示する。
- キャンセルはデータを変更せず、削除APIも呼び出さない。
- 確定後にAPIが成功した場合は削除完了メッセージを表示し、一覧から対象を除外する。
- APIが失敗した場合はエラーを表示し、成功メッセージや削除済み表示にしない。

登録用`POST /api/tasks`、更新用`PUT /api/tasks/{taskId}`、削除の取り消しは本機能の契約範囲外。
