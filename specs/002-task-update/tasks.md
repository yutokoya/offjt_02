# 実装タスク: タスク更新

## PR方針

- M2-01〜M2-10の各受け入れ条件を1つずつ独立したPRとして作成する。機能仕様に含まれないタスク登録・削除は追加しない。
- タスクの更新対象は、登録機能が提供する共通Taskの永続化モデルと一覧データを利用する。登録機能の永続化（M1-02）と一覧取得（M1-04）がmainに取り込まれてから、更新APIのPRを開始する。
- 担当者更新（M2-10）はREQ-UC002、機能仕様、データモデル、個別API契約で定義する。更新画面はGETで取得した担当者値を保持してPUTに含め、未設定を選んだ場合のみ`null`を送信する。共通API契約どおり、省略または`null`は未割当として扱う。
- 各PRには該当する受け入れ条件の実装とテストを含める。400行または8ファイルを超える見込みの場合は着手前に分割方法を再調整し、別の受け入れ条件を同じPRへ混在させない。

## PRと受け入れ条件

| PR順 | 受け入れ条件 | 実施内容 | 依存 |
|---|---|---|---|
| PR-01 | M2-01 | 一覧の編集操作から別の更新画面を開き、対象タスクの現在値を表示する | タスク登録M1-02、M1-04 |
| PR-02 | M2-02 | 有効な内容を対象Taskへ保存し、他の属性を維持する | PR-01、タスク登録M1-02 |
| PR-03 | M2-03 | 更新成功時に完了メッセージを表示する | PR-02 |
| PR-04 | M2-04 | 更新後の最新データを一覧に反映する | PR-02、PR-03、タスク登録M1-04 |
| PR-05 | M2-05 | タスク名・期限日の必須検証と失敗時の非更新を実装する | PR-02 |
| PR-06 | M2-06 | 空白除去後のタスク名をUnicodeコードポイント数で検証する | PR-05 |
| PR-07 | M2-07 | 説明をUnicodeコードポイント数で検証する | PR-05 |
| PR-08 | M2-08 | 期限日の形式と実在性を検証する | PR-05 |
| PR-09 | M2-09 | 存在しない、または削除済みの対象を404で拒否する | PR-02 |
| PR-10 | M2-10 | 担当者の設定・変更・未設定を保存して画面に反映する | PR-02、PR-04、タスク登録M1-09 |

PR-03・PR-04は更新成功後の表示を別々にレビューできるよう順に作成する。PR-05〜PR-08は共通の検証・エラー応答を再利用し、各PRでは指定された制約と境界テストだけを追加する。
