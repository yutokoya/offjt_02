# クイックスタート: タスク登録の検証

## 事前準備

- Java 21、Node.js 24、pnpm 10
- DockerとPostgreSQL 17

## 開発用データベースの起動

リポジトリのルートで実行する:

```bash
docker compose up -d postgres
```

## 自動検証

依存関係の初回セットアップ時または変更時に実行する:

```bash
pnpm --dir frontend install --frozen-lockfile
```

CIと同じ検証ゲートをリポジトリのルートから実行する:

```bash
bash scripts/gate.sh verify
```

このゲートはフロントエンドの整形・Lint・ビルド・テストと、バックエンドのCheckstyle・テストを実行する。バックエンドの統合テストには起動済みのPostgreSQLが必要である。

## 受け入れ確認の手順

1. フロントエンドとバックエンドを起動する。
2. タスク一覧から「タスク登録」を選び、登録専用画面が表示されることを確認する。登録画面が更新画面や削除確認UIと共用されていないことを確認する。
3. タスク名と過去日を含む期限日を入力し、任意で説明・担当者を入力して登録する。登録完了メッセージと一覧への反映を確認する。
4. 担当者を省略して登録し、一覧で「未割当」と表示されることを確認する。
5. 空白だけのタスク名、空白除去後101 Unicodeコードポイントのタスク名、201 Unicodeコードポイントの説明、未入力・形式不正・実在しない期限日で登録する。エラーが表示され、一覧や保存データが変更されないことを確認する。
6. バックエンドから`GET /api/tasks`を呼び出し、成功した登録結果が`items`に含まれることを確認する。

開発用PostgreSQLを停止する場合:

```bash
docker compose down
```

`docker compose down`はデータボリュームを削除しない。
