# 実装タスク: タスク登録

## PR方針

- M1-01〜M1-09の各受け入れ条件を1つずつ独立したPRとして作成する。受け入れ条件をまたぐ機能追加は同じPRに含めない。
- M1-01は登録画面と一覧を分け、4項目を表示する変更がPR #18でmainにマージ済みのため、追加PRを作らない。
- 各PRには、その受け入れ条件に必要な実装とテストを含める。変更が400行または8ファイルを超える見込みの場合は着手前に分割方法を再調整し、別の受け入れ条件を同じPRへ混在させない。
- 登録計画の実装フェーズは技術的な作業順を示し、PR境界を定めるものではない。PR境界はこのファイルの表を正とする。PR-02の変更が上限を超える場合はM1-02の範囲内で分割し、別の受け入れ条件を同じPRに含めない。
- M1-02で共通Taskの永続化基盤を作り、以降の登録・一覧・入力検証PRはその基盤へ追加する。M1-09の担当者列を共通テーブルに先行して含めてもよいが、担当者の入出力・表示の受け入れはM1-09で完了させる。
- 既存の登録スケルトンで表示できることと、業務機能の受け入れ完了を区別する。登録APIが未実装の状態で成功メッセージを返さない。

## PRと受け入れ条件

| PR順 | 受け入れ条件 | 実施内容 | 依存 |
|---|---|---|---|
| PR-01 | M1-01 | 登録画面にタスク名・説明・担当者・期限日を表示する。PR #18で対応済み | 完了 |
| PR-02 | M1-02 | 共通Taskの永続化と登録APIの正常系を実装する | PR-01 |
| PR-03 | M1-03 | 登録成功時に完了メッセージを表示する | PR-02 |
| PR-04 | M1-04 | 保存済みタスクを一覧取得し、新規登録したタスクを一覧に反映する | PR-02、PR-03 |
| PR-05 | M1-05 | タスク名・期限日の必須検証、空白のみの名前の拒否、エラー表示と非保存を実装する | PR-02 |
| PR-06 | M1-06 | 空白除去後のタスク名をUnicodeコードポイント数で検証する | PR-05 |
| PR-07 | M1-07 | 説明をUnicodeコードポイント数で検証する | PR-05 |
| PR-08 | M1-08 | 期限日の形式と実在性を検証する | PR-05 |
| PR-09 | M1-09 | 任意の担当者を保存し、登録後に入力値または未割当を確認できるようにする | PR-04 |

PR-03とPR-04は、成功メッセージと一覧反映が別々にレビューできるよう順に作成する。PR-05〜PR-08は共通の検証・エラー応答を再利用し、各PRでは指定された受け入れ条件の制約と境界テストだけを追加する。
