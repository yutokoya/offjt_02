# タスク登録API契約

共通エラー形式・フィールド制約は[API契約](../../../docs/design/api-contract.md)に従う。データ形式にはJSONを使用する。

## タスク一覧

`GET /api/tasks`

- `200 OK`: 通常一覧に表示するタスクを返す。論理削除済みタスクは含めない。

応答例:

```json
{
  "items": [
    {
      "taskId": 101,
      "taskName": "API契約を確認する",
      "description": null,
      "assigneeName": null,
      "dueDate": "2026-11-18"
    }
  ]
}
```

## タスク登録

`POST /api/tasks`

要求:

```json
{
  "taskName": "  API契約を確認する  ",
  "description": "入出力とエラー応答を確認する",
  "assigneeName": "参加者A",
  "dueDate": "2026-11-18"
}
```

- `taskName`: 必須。前後のUnicode空白を除去して保存し、空となる値と、除去後100 Unicodeコードポイントを超える値を拒否する。
- `description`: 任意。省略または`null`を許可する。入力値が200 Unicodeコードポイントを超える場合は拒否する。
- `assigneeName`: 任意。省略または`null`は未割当として保存する。
- `dueDate`: 必須。厳密な`YYYY-MM-DD`形式の実在日付を受け付ける。過去日は拒否しない。

成功応答:

- `201 Created`
- `Location: /api/tasks/{taskId}`
- 本文は作成したTaskを返す。

```json
{
  "taskId": 101,
  "taskName": "API契約を確認する",
  "description": "入出力とエラー応答を確認する",
  "assigneeName": "参加者A",
  "dueDate": "2026-11-18"
}
```

エラー応答:

| ステータス | 意味 |
|---|---|
| `400 Bad Request` | 必須項目、文字数、期限日の検証失敗。共通エラー形式を返し、保存しない |
| `500 Internal Server Error` | 予期しない保存失敗。共通エラー形式を返し、成功扱いにしない |

入力検証と登録は一処理として扱い、検証失敗時に部分保存を残さない。登録成功後の一覧表示には、応答本文の作成済みTaskを使用できる。

## 画面操作の契約

- タスク一覧から登録操作を選択すると、更新画面と分離された登録専用画面を表示する。
- 登録画面にはタスク名、説明、担当者、期限日の入力欄を表示する。
- 入力エラーまたはAPIエラーは利用者に表示し、登録成功として扱わない。
- 登録成功時は完了メッセージを表示し、作成済みTaskを一覧に反映する。
- 本契約は登録と一覧取得に限定し、タスク更新・削除、作業時間、ステータス、依存関係を含まない。
